# 网页新增施工地点

本次为 Part A 前端原型增加地点录入和关联公告，不接入数据库或管理员账号系统。

## 使用

1. 打开 Impact Map，点击 **+ Add / manage locations**。
2. 填地点名称、区域；手动输入纬度和经度，或者点击 **Pick coordinates on map**，在地图空白处或已有标记上点选。取消选择或按 Esc 会返回表单，保留已经填好的内容。
3. 填公告标题、类型、开始/结束日期、影响和通行说明。选择作业示例，或者选择引用已发布公告并填写公告标题和公开来源网址；来源发布日期选填。
4. 点击 **Save location**。关闭面板后即可查看新标记。它与一条新公告关联，在区域、类型和关键词筛选中可找到，也能从详情打开公告并返回地图。

在 **Your saved locations** 中可以编辑、删除自己新增的记录；内置三个示例地点不受影响。修改坐标后地图标记会移动。删除地点会一并删除其本地关联公告。

## 坐标和来源

录入范围与现有槟城原型地图一致：纬度 5.255–5.460，经度 100.190–100.435。Google Maps、Street map 需要联网；示意图可离线使用。示意图点选会明确标记为近似坐标，也可以之后手动修改。点选仅确定地理位置，不能证明该处存在施工。

原有三个地点及四条公告均为虚构示例。用户录入的引用会显示来源标题、网址、发布日期（如有）和坐标获取方式，并标明未经核实。系统不会自动从 Google Maps 获取真实施工通知，也不会自动验证所填来源。

## 保存与备份

数据保存在当前浏览器的网站存储 `mutiaraconnect.locations.v1`，与组员的反馈记录分开。相同浏览器、相同网站地址下刷新仍保留；更换电脑、浏览器或网站端口不会自动同步。清除网站数据也会删除本地记录。

点击 **Export backup** 下载 JSON；在另一处打开地图并选择 **Import location backup** 即可恢复。导入只新增不存在的引用，不覆盖现有同 ID 记录；无效文件不会部分写入。备份不包含 Google Maps Key 或反馈记录。GitHub 保存网站代码，不保存用户浏览器内的施工记录。

推荐使用固定的本地 HTTP 地址查看多个页面。直接双击 HTML 时，浏览器对不同文件的存储共享行为可能不同；地图与本地公告详情之间的链接会携带选中记录。可用导出/导入在不同打开方式间转移记录。

## 实现与验证

- `js/location-store.js`：验证、存储、导出/导入和公告/地点转换。
- `js/location-editor.js`：表单、点选、编辑、删除及备份界面。
- `js/map.js` / `js/google-map.js`：标记同步、点选坐标及视野调整。
- `js/app.js`：新增公告参与列表筛选、详情及地图跳转。
- `tests/location-store.cjs`：24 项存储与边界检查。
- `tests/location-editor-browser.cjs`：37 项浏览器功能检查；Google 接口部分模拟，无在线 OSM 瓦片请求。
- `tests/location-editor-live.cjs`：8 项真实 Google 检查，包括点选、保存、改坐标、刷新及标记未被面板遮挡。只在私有本地配置可用时运行，不输出 Key。

另已复核原有地图布局、Google 切换/断网回退、跨模块反馈提交/查询、Street map 链接及首次配置保留。结果和截图在 `location-editor-qa/`。本地文件模式只验证了数据链接和访问控制逻辑，未重新运行真实浏览器文件导航；真实 Google 新增流程在 HTTP 下验证。

这项补充不是已完成的工作人员后台或全用户共享发布服务；相应管理员流程仍由负责后台模块的组员接入。
