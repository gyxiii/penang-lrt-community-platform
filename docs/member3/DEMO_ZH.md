## 开始前

1. 优先使用当前项目工作副本，保持目录结构；旧ZIP的职责说明已过时，不能作为当前完整M3交付。
2. 双击项目中的 `打开网站.cmd`，确认首页、公告、地图和反馈页能打开。
3. 确认Submit Feedback和Track Feedback可用，准备示例编号MC-FB-DEMO-003。
4. 准备英文稿中的虚构表单内容，可直接粘贴，避免录制时长时间打字。
5. 始终使用同一浏览器、同一来源。不要在直接打开 HTML 与不同端口的本地网站间切换后，还期待新记录共享。

## 操作顺序

| 时间参考 | 画面 | 重点 |
| --- | --- | --- |
| 0:00–0:20 | 首页 → Submit Feedback | 介绍反馈提交与跟踪模块 |
| 0:20–1:30 | 反馈表单 | 简短展示空字段校验，填写虚构案例并提交；照片可选 |
| 1:30–2:00 | 成功回执 | 展示编号和摘要，进入 Track this feedback |
| 2:00–3:00 | 新报告 → 刷新 → 示例 MC-FB-DEMO-003 | 新报告仍为 Submitted；另一个示例用来展示处理历史及回应 |
| 3:00–3:30 | 查询MC-FB-NOTFOUND → 返回示例003 | 演示查无记录提示和恢复；需要缩短时可省略 |
| 3:30–4:00 | 示例跟踪页 | 说明浏览器本地模拟范围及正式后台待接入 |

上述时间是排练参考，不是固定必须达到的时长。若打字、附件或切换页面耗时，应精简讲解，不要超过小组分配时间。

## 应当讲清楚

- 新提交成功的反馈会得到唯一编号，并在同一浏览器中可查询。
- 三个内置示例分别展示 Submitted、In Progress、Responded。
- 新反馈不会自动变成已处理；展示回应时应明确切换到了另一个虚构示例。
- 全平台UI图库仅为可复用公共素材，不必放入个人片段。它不替代报告中的时序图。
- 正式后台由其负责人接入；独立后台设计稿不会更新公众已保存反馈。
- 正式后台未完成前，演示自己的片段不要点击公共导航里的 Admin，以免打开尚不存在的页面。
